# Stonecrab alpha plan

Updated: 2026-10-27. Baseline: commit c825b9d (docs) over implementation baseline e7d887e.
Status: proposed. Decisions D1-D23 are recommendations awaiting maintainer confirmation; P1-P5 are maintainer actions outside code. Slices land in the dependency order of the table below, one signed Conventional Commit per slice with every coverage gate green.
Angle: parity and evidence first. Every wire and address behavior that ships has a source-checked parity row with a stable id, a retained vector and a test id before it is called implemented; the public driver boundary lands only together with the simulator that exercises it; one unmodified example program defines done. Scope is cut to what that evidence can cover.

## Alpha definition

The alpha is the first public pre-release in which an application can, through `DriverRegistry` -> `dyn Driver` -> `dyn Connection`, connect to a Modbus TCP server by the upstream connection-string grammar (`modbus-tcp://host:502?default-unit-identifier=1`), read coils, discrete inputs, holding registers and input registers as the 15 upstream numeric/bit types (BOOL, BYTE, WORD, DWORD, LWORD, SINT, USINT, INT, UINT, DINT, UDINT, LINT, ULINT, REAL, LREAL; one element per tag) in a correlated, request-ordered batch with `split_into` disclosure, observe `ConnectionState` through a `StateWatch` including request-driven reconnect with capped jittered backoff, and cancel or time out any operation with documented wire consequences.

Definition of done: `crates/stonecrab/examples/profile_read.rs`, unmodified, loads a synthetic TOML profile that explicitly declares its address convention, builds tags through `Driver::parse_address(text, &AddressOptions)` with options derived from the profile (the plain `modbus_tcp_read.rs` example derives them from `ConnectionConfig::address_options()` before `connect` consumes the config), reads with a 500 ms deadline and emits name, value, unit, quality, raw value and `sampled_at` for every measurement through `tracing::info!` on a `fmt` subscriber the example installs, with `source_time` absent and `split_into` disclosed, then closes and returns `std::process::ExitCode` (`FAILURE` under `--expect-good` when any quality is not `Good`). It runs in CI against pymodbus 3.8.6 (`STONECRAB_URL=modbus-tcp://127.0.0.1:5020?address-convention=plc4x`, the `modbus-tcp` profile variant) and against the simulator with no network (`sim://bench`, the `sim` variant). No library item may exist only to serve an example; every item an example calls is exercised by the contract suite or a driver test.

Support levels use only the four labels of SPEC.md 'Hardware evidence':

Not claimed, each visible as a deferred parity row or release-note line: Modbus write operations (`Connection::write` exists; `modbus-tcp` reports `write: false` and rejects writes before I/O; the simulator implements write so the contract has a real exerciser), subscriptions native or polling, browse, discovery (pcap upstream), ping, RTU/ASCII, UDP/TLS/TLS-PSK/test transports, extended registers (FC20/21), array selections, STRING/WSTRING/CHAR/WCHAR and the TIME/DATE family, the upstream gap-filling read optimizer, calendar/bytes/list/raw values, named device profiles, stale tracking and polling loops, background reconnect tasks, MSpec generation, differential tests, soak, benchmarks, hardware evidence, and the non-Modbus parts of the M0 inventory. This is a disclosed subset of SPEC.md 'Delivery milestones' M1: the read contract, per-crate coverage gates, adverse transport, independent server and hardware disclosure criteria are met; write staging is deferred as SPEC.md 'Protocol delivery order' permits ("Write support is staged, not abandoned").

Versions and tags: `stonecrab` 0.2.0; `stonecrab-core`, `stonecrab-codec`, `stonecrab-transport`, `stonecrab-driver-sim`, `stonecrab-modbus`, `stonecrab-sensors` 0.1.0; the facade pins siblings with `=` ranges (CODING_STANDARDS.md section 20.1); signed tags `<crate>-v<version>` (section 20.2); the GitHub release is flagged pre-release and titled alpha. Plain pre-1.0 versions rather than `-alpha.N`: STATUS.md records `stonecrab` 0.1.0 as the only published version, so Cargo's resolver would answer `cargo add stonecrab --features modbus` with the placeholder and an unknown-feature error unless users spell the pre-release; `=` sibling ranges and the later `semver-checks` baseline stay simple. 0.2.0 rather than 0.3.0 because CHANGELOG.md already carries the unreleased `stonecrab 0.2.0` section with the `placeholder::status` removal and nothing has been published since 0.1.0. Alpha status is stated in the README first paragraph, crate docs, crates.io descriptions, CHANGELOG and release notes. Publication is a separate maintainer action requiring approval.

## Workstreams and ordered slices

One PR per slice: Conventional Commit with a CODING_STANDARDS.md section 18.2 scope (crate short name, `docs`, `ci`, or none; the facade has no section 18.2 scope, so facade slices carry none), DCO sign-off, under about 600 handwritten lines including tests (section 18.4), CHANGELOG `Unreleased` entry per touched published crate, packaging allow-list and mise/CI edits for any new crate or file, `// covers:` tags on mandatory-case tests, a `# Compatibility: docs/parity/<file>.md#<row-id>` rustdoc section on every public item whose behavior maps to upstream PLC4X behavior (section 12.2), `# Errors` listing its `ErrorKind`s on every `Result`-returning public fn, a compiling `# Examples` doctest on every public type's primary constructor and every top-level operation (simulator-based or `no_run` with a stated reason, never `ignore`; section 12.1), `# Cancel safety` and `# Wire effects` on every `OpFuture`-returning or transmitting fn with the deadline source stated there or in the summary (section 8.5), tracing span fields `scheme`, redacted `endpoint`, `op` and `txn`/`request_id` on every per-operation span (section 14.2), `[workspace.dependencies]` versions as minor-level caret ranges (section 15.4: `version = "1.<minor resolved in Cargo.lock at PR time>"`), the D23 `cargo tree -i` check whenever a dependency is added, and every new public type added to that crate's `tests/public_types.rs` `assert::<T: Send + Sync + 'static>()` list (section 9.11). ## Risks and mitigations

- Inventory stall: S01 transcribes the completed audit, bounded to the read subset, with a greppable exit; open M0 items are named as non-gating.
- Vector transcription error becoming decoder truth: originals retained verbatim; the parser-suite `.hex` re-derived from `<raw>` by string scan; driver-suite vectors produced by a deterministic `roxmltree` adapter from the XML models, never from our decoder; the all-datatypes step format and "Query/Response" case structure are UNVERIFIED until S04b enumerates them, so S23's fixture count is provisional and S04b fails rather than guesses on an unknown shape.
- Banned transitive crates breaking the blocking `deny` job: `tracing` -> `tracing-core/std` -> `once_cell` and `tracing-subscriber` `fmt` -> `sharded-slab` -> `lazy_static` are handled by `wrappers` entries recorded in ADR-0012 and ADR-0014 with audit entries; every dependency-adding slice runs the D23 `cargo tree -i` check before the PR opens and records any further path (`thread_local`, `proptest` `std`, UNVERIFIED) the same way; `exclude-dev` is never set.
- 100% aggregate gate versus socket code: ADR-0005 tiers land in S03 before any new crate; uncovered OS-dependent arms named per PR (first: real-socket connect timeout); error paths never excluded; the facade's empty line set is handled explicitly.
- `wildcard_enum_match_arm` on foreign `#[non_exhaustive]` enums (UNVERIFIED): matches over core enums live in core helpers; S11b-1 settles it and ADR-0005 records the outcome.
- Hand-written waker primitives (token, watch, FakeClock): each small, tested with `Waker::noop` polling and wake assertions, `future_not_send` lint, no lock across `.await`; the transport pending slot uses `tokio::sync` instead of a hand-rolled queue; the simulator has no queue at all (single flag, `Backpressure`).
- Clock mismatch between application deadlines and a simulator clock: `SimDriver::new()` uses `RealtimeClock` (D9); injected clocks are documented as the deadline reference.
- Paused-time flakiness on real sockets: timing on `FakeTransport`/`FakeClock` only; loopback tests byte-level; macOS/Windows cells blocking with a documented escape (D21).
- Docker and PyPI availability in CI: digest-pinned base image, pinned pymodbus, bounded readiness probe, evidence artifact per run.
- Upstream grammar holes (`4x:INT`, odd offsets, overlong digits, ambiguous bare `40001`, unbounded `unit-id`): adversarial table from the verified regexes plus `fuzz_modbus_address`; bare short forms require an explicit convention; sim and driver configuration parsers get the same section 13.7 and property treatment plus `fuzz_modbus_connection_string`.
- Convention routing with no executable path: `AddressOptions` is the single carrier (URI option -> `ConnectionConfig::address_options()`; profile field -> `tags()`), the trait takes it explicitly, and both examples exercise it in CI.
- Byte/word-order mapping derived, not yet vector-confirmed: parity row cannot become `automated-verified` before S23 passes the little-endian vectors.
- `#[expect]` attributes on `UnknownReason`/`WriteOutcome`: untouched; S09 asserts both still fire.
- Tooling on pinned toolchains: cargo-geiger (UNVERIFIED) has the grep fallback; llvm-cov doctest instrumentation assumed absent so every public function has a unit test and the per-slice `# Examples` rule is enforced by review; the report command, its empty-set behavior and `disallowed-methods` resolution with tokio are checked in S03 and S16.
- Dependency growth (tokio, tracing, tracing-core/once_cell wrapper, serde, serde_json, roxmltree, toml, proptest, libfuzzer-sys, arbitrary, tracing-subscriber, sharded-slab/lazy_static wrapper): ADR-0009/0012/0014/0016 and one audit entry per dependency in the PR that adds it, `default-features = false` with named features and minor-level caret ranges, `machete` and `deny` jobs, the fuzz workspace audited separately.
- Dev-dependency cycle core -> testkit -> transport -> core: doubles used only from `tests/` directories; the facade archive no longer ships `tests/**` (S02).
- Request-driven reconnect surprising users expecting self-healing connections: documented in the modbus README and ADR-0014; eager reconnect is the first M2 slice.
- Single maintainer versus two approvals: waiver recorded in ADR-0005 at S03 with Appendix C self-review and an expiry condition; toolchain bump mid-stream: one reserved `build:` slice touching ci.yml, rust-toolchain.toml, mise.toml, Cargo.toml, clippy.toml, README, STATUS.
- Scope creep into writes and polling: contract suite asserts `write = false` for `modbus-tcp` and `subscribe = Unsupported` for both drivers; the deferral table names the owning milestone.
- Oversized slices: S04, S11b, S20, S25 and S28 are split (S04a/S04b, S11b-1/S11b-2, S20a/S20b, S25/S25b, S28a/S28b) so every PR stays under section 18.4's target; crate-creation slices carry README/LICENSE/NOTICE from the start so no late documentation PR exceeds it.
