# Siemens S7 parity record
Baseline: `upstream/manifest.toml`, Apache PLC4X v1.0.0 (tag `v1.0.0`),
commit `ea229918f5d07700e04d7d69ab1645da679cb700`.

State (slice S43): nothing is implemented. Every row is `planned` or `deferred`. The S7
driver and its COTP transport are milestone M4 (`docs/POST_ALPHA_PLAN.md` section 4,
decision E5: S7 or EtherNet/IP first, decided when a test PLC is available). The record
covers the Java driver `plc4j/drivers/s7` (manifest `inventory.s7`), the COTP transport
(`inventory.transport_cotp`) and the Go and C counterparts (`inventory.go_s7`,
`inventory.c_s7`). No `[[backlog]]` row in the manifest names S7, Go or C S7; the non-Java
differences are recorded from the `LANG GAP` notes of those two entries under "Backlog
from other languages". PLC4Python has no S7 driver and PLC4Net has none either.

Status vocabulary, as used in the Status column:

- `planned (Mn)`: Stonecrab will port the behavior in milestone Mn. The Test ids column
  names at least one test id prefixed `planned:`; no such test exists yet.
- `deferred (<reason>)`: Stonecrab does not port the behavior now. The reason is a
  non-Java-only capability, an upstream placeholder, a defect that is not reproduced, or a
  plan decision. Deferred rows may carry `none` as test id.
- `implemented`, `automated-verified` and `hardware-verified` are not used yet. When a
  row reaches them the `planned:` prefix goes and the test ids must name real tests, as
  `scripts/parity-check.sh` enforces. A hardware claim needs the device model and firmware
  in the Test ids column, as the compatibility baseline in `docs/SPEC.md` requires.

Unimplemented upstream placeholders do not become obligations; they are listed as
`deferred (upstream placeholder)` so the omission is visible. Row ids are stable and never
renumbered.

## Capabilities
Upstream reports capability through two signals that disagree. The driver flags say
`canPing`, `canRead`, `canWrite`, `canDiscover` true and leave `canBrowse` and
`canSubscribe` at the false default (`s7.driver_caps`, Drv:101-114; `s7.driver_discovery`,
Drv:204-235). The per-connection metadata is what callers see: read and write always,
subscribe and browse only when UserData services are available (`s7.conn_metadata`,
Conn:169-183). The manifest marks the driver-level flags as UNCERTAIN because no SPI code
reads them. Stonecrab reports the connection-level truth.

| Row id | Upstream behavior (manifest key or path:lines) | Planned Stonecrab behavior | Status | Test ids |
