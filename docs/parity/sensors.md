# Sensors record
Status: schema and loader implemented in slice S28a (ADR-0016). Stonecrab-owned: no
upstream behavioral parity claim.

Apache PLC4X has no sensor profile concept. It describes devices through driver address
strings and MSpec-generated data types, and it has no declarative file that maps addresses
to named, scaled, qualified measurements; `upstream/manifest.toml` inventories nothing to
compare against. The rows below therefore record Stonecrab's own sensor profile contract
(SPEC.md "Sensor profile contract") so that rustdoc `# Compatibility` sections have a
stable target and tests have ids to cite. Each row's "Upstream behavior" column says "none".

| Row id | Upstream behavior | Stonecrab behavior | Status | Test ids |
| --- | --- | --- | --- | --- |
| SENSORS-SCHEMA-V1 | None (no profile concept upstream). | Schema version 1 is a TOML document read by `SensorProfile::from_toml` behind the default `toml` feature: size-bounded at 64 KiB before parsing, unknown keys denied at every level, `schema_version` read first so any value other than 1 is `IncompatibleSchema { found }`, errors reduced to a line and column and never echoing the document, every error `InvalidConfig` as a `PlcError`. `ProfileId`, `SchemaVersion`, `DeviceApplicability`, `ConnectionRequirements` (scheme, explicit `address_convention`, options), `Provenance` and `ValidationStatus` are the document's top level; nothing is serialized by the library. | implemented | `schema_version_2_is_rejected_as_incompatible`, `a_missing_or_mistyped_schema_version_is_a_syntax_error`, `the_size_bound_is_checked_before_parsing`, `an_empty_document_is_a_syntax_error_without_echo`, `the_minimal_profile_loads_with_defaults`, `an_unknown_field_is_rejected_at_every_level`, `a_wrong_typed_field_is_a_syntax_error_at_its_position`, `missing_required_keys_are_rejected`, `invalid_toml_is_a_syntax_error_with_a_position`, `errors_never_echo_the_document`, `hostile_nesting_is_rejected_without_exhausting_the_stack`, `profile_id_boundaries`, `profile_id_boundaries_apply_in_documents`, `every_validation_status_loads`, `schema_version_validates_directly`, `profile_errors_convert_to_invalid_config`, `arbitrary_text_never_panics`, `arbitrary_toml_like_text_never_panics`, `a_valid_document_with_one_inserted_character_never_panics`, `a_valid_document_cut_anywhere_never_panics`, `accepted_identifiers_are_snake_case`, fuzz target `fuzz_sensors_profile_toml`, doctests `SensorProfile::from_toml`, `ProfileId`, `SchemaVersion`, `ProfileError` |
| SENSORS-MEASUREMENTS | None. | `MeasurementDef` carries the name (snake_case, doubling as the `TagId`), address text and driver type name passed through unchanged, `count` (default 1), optional `byte_order` and `word_order` that are never inferred, an ordered `ScaleStep` pipeline (`multiply`, `divide`, `offset`, `clamp`, `bit_field`), unit, optional range, `StatusField`s and a `QualityMapping` by status field name, `min_interval_ms` and `stale_after_ms` as whole milliseconds, and `keep_raw` (the unscaled typed value, not wire bytes).
