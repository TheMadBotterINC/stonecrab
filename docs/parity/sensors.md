# Sensors record
Status: schema and loader implemented in slice S28a, validation and the unit table in
slice S28b, tags and the measurement pipeline in slice S29 (ADR-0016). Stonecrab-owned:
no upstream behavioral parity claim.

Apache PLC4X has no sensor profile concept. It describes devices through driver address
strings and MSpec-generated data types, and it has no declarative file that maps addresses
to named, scaled, qualified measurements; `upstream/manifest.toml` inventories nothing to
compare against. The rows below therefore record Stonecrab's own sensor profile contract
(SPEC.md "Sensor profile contract") so that rustdoc `# Compatibility` sections have a
stable target and tests have ids to cite. Each row's "Upstream behavior" column says "none".
