# Transport record
Status at the alpha (slice S31): implemented in slices S16, S18 and S19 (ADR-0014); the
serial rows were added by S58 (ADR-0014, addendum S58). No upstream behavioral parity
claim. The rows are checked on loopback sockets, the in-memory
`FakeTransport` and the fake clock; the Modbus driver exercises the TCP transport, the
framing layer and the guard against pymodbus 3.8.6 in the `interop` job, which is
evidence for `MB-TCP-CONNECT` and the read rows in `docs/parity/modbus.md`. Since S52b the
`interop-toxiproxy` job also drives them on real sockets and a real clock through Toxiproxy
(resets, black holes, latency, sliced frames, closed links) and against a paused and a killed
peer; its tests are listed in `TRANSPORT-DEADLINES`, `TRANSPORT-STREAM-DELIVERY`,
`TRANSPORT-FRAMING`, `TRANSPORT-RESYNC` and `TRANSPORT-RECONNECT`, and no status changes.
Every row of the first table below has real test ids and is named by a `# Compatibility`
section or a test (`scripts/parity-check.sh`).
The section "Upstream transports" at the end of this file (slice S43) maps each upstream
transport to a Stonecrab transport or slice with `planned` and `deferred` rows only.

Apache PLC4X (PLC4J) builds its transports on Netty channels, pipelines and handlers;
there is no upstream transport behavior inventoried in `upstream/manifest.toml` to compare
against, and the Modbus connection-string options that concern transports are recorded in
`docs/parity/modbus.md` (`MB-TCP-TRANSPORTS`). The rows below therefore record Stonecrab's
own transport contract so that rustdoc `# Compatibility` sections have a stable target and
tests have ids to cite. Each row's "Upstream behavior" column says "none" where there is
nothing to compare.

## Upstream transports
Slice S43 adds this section so that every upstream transport has a visible row. The rows
above record Stonecrab's own transport contract and are `implemented`. The rows below map
each upstream transport entry of `upstream/manifest.toml` (`inventory.transport_*`, pinned
commit `ea229918`) to the Stonecrab transport or slice that covers it. Nothing below is
implemented: every row is `planned (<milestone or slice>)` with a `planned:` test id, or
`deferred (<reason>)` with test ids `none`, and `scripts/parity-check.sh` therefore does
not ask for a code reference. A planned test id is a name chosen now, not an existing test.

Status vocabulary for this section: `planned (Mn)` is a behavior Stonecrab will port in
that milestone of `docs/POST_ALPHA_PLAN.md` section 4 (a slice number is added where the
plan names one); `deferred (<reason>)` is a behavior Stonecrab does not port now, with the
reason (a non-Java capability, a first-party equivalent, an upstream placeholder or a
platform limit). Citations use the manifest key and `file:lines` of the cited entry, for
example `transport_tcp.config` is `TcpTransportConfiguration.java:26-96`. Every upstream
transport is client only and the Stonecrab rows keep that.
