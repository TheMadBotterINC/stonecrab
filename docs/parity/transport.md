# Transport record
Status: implemented in slice S16 (ADR-0014). No upstream behavioral parity claim.

Apache PLC4X (PLC4J) builds its transports on Netty channels, pipelines and handlers;
there is no upstream transport behavior inventoried in `upstream/manifest.toml` to compare
against, and the Modbus connection-string options that concern transports are recorded in
`docs/parity/modbus.md` (`MB-TCP-TRANSPORTS`). The rows below therefore record Stonecrab's
own transport contract so that rustdoc `# Compatibility` sections have a stable target and
tests have ids to cite. Each row's "Upstream behavior" column says "none" where there is
nothing to compare.

| Row id | Upstream behavior | Stonecrab behavior | Status | Test ids |
| --- | --- | --- | --- | --- |
| TRANSPORT-TCP-CONNECT | None inventoried (Netty bootstrap, outside the Modbus file inventory). | `TcpFactory::open` resolves `Endpoint::Tcp` with `lookup_host` and tries the addresses in order, all inside the connect deadline; `Endpoint::Custom` is `InvalidConfig`; a refused or reset connect is `Disconnected` with `Diagnostics.operation = Connect`; `TCP_NODELAY` follows `TcpFactory::nodelay` (default true). A connect deadline that expires on a real socket is not tested (ADR-0014, named uncovered arm). | implemented | `connecting_to_a_closed_loopback_port_is_disconnected_before_the_deadline`, `the_opened_transport_reports_its_peer_and_limits`, `a_custom_endpoint_is_rejected_as_invalid_config`, `connect_first_skips_a_refused_address_and_takes_the_next`, `nodelay_follows_the_factory_setting`, doctest `TcpFactory` |
| TRANSPORT-DEADLINES | None inventoried (Netty read-timeout handlers, outside the Modbus file inventory). | Every `Transport` call takes a `Deadline`, the only deadline source. An elapsed deadline fails with `Timeout` before any I/O; one that passes while the call waits fails with `Timeout` through one private `timeout_at` helper; a dropped or timed-out `recv` loses nothing; a `send` cut short poisons the transport (later calls `Disconnected`); `shutdown` is idempotent and closes from its first poll. `SystemClock::now()` is Tokio's instant, so paused-time tests agree with `Deadline`. No task is spawned and nothing runs between calls (D15). | implemented | `a_pending_io_future_fails_with_timeout_when_the_deadline_passes`, `an_elapsed_deadline_fails_even_if_the_io_future_is_ready`, `an_elapsed_deadline_fails_with_timeout_before_any_io`, `io_failures_map_to_disconnected_except_a_connect_timeout`, `errors_carry_transport_diagnostics_and_the_io_source`, `a_dropped_recv_loses_nothing`, `a_send_cut_short_poisons_the_transport`, `a_write_failing_on_a_reset_connection_is_disconnected_and_poisons`, `shutdown_completes_tells_the_peer_and_closes_the_transport`, `now_follows_paused_tokio_time_so_deadlines_agree`, `sleep_until_waits_for_tokio_time_and_resolves_immediately_when_past`, `a_dropped_sleep_has_no_effect`, `wall_now_is_the_system_wall_clock` |
| TRANSPORT-BUFFER-BOUND | None inventoried (Netty decoders bound frame length per protocol). | `recv` appends at most `max_buffered_bytes - buffer.len()` bytes and fails with `ResourceLimit`, reading nothing, when the buffer is already at or above the bound; `send` refuses a payload over `max_frame_bytes` with `ResourceLimit` and sends nothing; `FrameError::Oversized` maps to `ResourceLimit`, `Truncated` and `Malformed` to `MalformedData` (D22, no codec dependency). | implemented | `recv_refuses_a_full_buffer_without_reading`, `recv_reads_no_more_than_the_free_space`, `send_refuses_a_frame_over_the_limit_and_sends_nothing`, `each_variant_maps_to_its_error_kind_and_keeps_the_source`, `display_names_the_size_and_never_a_payload`, doctest `FrameError` |
| TRANSPORT-STREAM-DELIVERY | None inventoried. | TCP is a byte stream: a frame may arrive over several `recv` calls (fragmentation) and one `recv` may return several frames (coalescing); `recv` returns the bytes that arrived and does not frame. `0` means the peer closed, after which every call fails with `Disconnected`; a reset surfaces as `Disconnected` too. | implemented | `a_frame_written_in_fragments_accumulates_across_recv_calls`, `two_frames_written_together_arrive_in_one_recv`, `peer_close_mid_frame_reads_zero_then_every_call_is_disconnected`, `a_connection_reset_surfaces_as_disconnected`, `send_delivers_the_bytes_in_order`, `a_boxed_transport_can_be_driven_from_another_worker_thread` |

Reconnect jitter (`Jitter::next_unit`) feeds `ReconnectPolicy::next_delay`, whose row is
`CORE-RECONNECT-POLICY` in `docs/parity/core.md`; its tests are
`samples_stay_in_the_half_open_unit_interval`, `the_state_does_not_fall_into_a_short_cycle`,
`samples_are_spread_over_the_interval`, `a_zero_seed_is_replaced_and_the_same_seed_repeats`
and `independently_seeded_generators_differ_and_are_never_zero`.
