# Transport record
Status: implemented in slices S16 and S18 (ADR-0014). No upstream behavioral parity claim.

Apache PLC4X (PLC4J) builds its transports on Netty channels, pipelines and handlers;
there is no upstream transport behavior inventoried in `upstream/manifest.toml` to compare
against, and the Modbus connection-string options that concern transports are recorded in
`docs/parity/modbus.md` (`MB-TCP-TRANSPORTS`). The rows below therefore record Stonecrab's
own transport contract so that rustdoc `# Compatibility` sections have a stable target and
tests have ids to cite. Each row's "Upstream behavior" column says "none" where there is
nothing to compare.

| Row id | Upstream behavior | Stonecrab behavior | Status | Test ids |
| --- | --- | --- | --- | --- |
| TRANSPORT-TCP-CONNECT | None inventoried (Netty bootstrap, outside the Modbus file inventory). | `TcpFactory::open` resolves `Endpoint::Tcp` with `lookup_host` and tries the addresses in order, all inside the connect deadline; `Endpoint::Custom` is `InvalidConfig`; a refused or reset connect is `Disconnected` with `Diagnostics.operation = Connect`; `TCP_NODELAY` follows `TcpFactory::nodelay` (default true). A connect deadline that expires on a real socket is not tested (ADR-0014, named uncovered arm); the expiry arm is covered on `FakeTransportFactory` and `FakeClock`. | implemented | `connecting_to_a_closed_loopback_port_is_disconnected_before_the_deadline`, `the_opened_transport_reports_its_peer_and_limits`, `a_custom_endpoint_is_rejected_as_invalid_config`, `connect_first_skips_a_refused_address_and_takes_the_next`, `nodelay_follows_the_factory_setting`, doctest `TcpFactory`, `a_scripted_connect_timeout_parks_until_the_clock_passes_the_deadline` (testkit) |
| TRANSPORT-DEADLINES | None inventoried (Netty read-timeout handlers, outside the Modbus file inventory). | Every `Transport` call takes a `Deadline`, the only deadline source. | TRANSPORT-BUFFER-BOUND | None inventoried (Netty decoders bound frame length per protocol). | `recv` appends at most `max_buffered_bytes - buffer.len()` bytes and fails with `ResourceLimit`, reading nothing, when the buffer is already at or above the bound; `send` refuses a payload over `max_frame_bytes` with `ResourceLimit` and sends nothing; `FrameError::Oversized` maps to `ResourceLimit`, `Truncated` and `Malformed` to `MalformedData` (D22, no codec dependency). | implemented | `recv_refuses_a_full_buffer_without_reading`, `recv_reads_no_more_than_the_free_space`, `send_refuses_a_frame_over_the_limit_and_sends_nothing`, `each_variant_maps_to_its_error_kind_and_keeps_the_source`, `display_names_the_size_and_never_a_payload`, doctest `FrameError` |
| TRANSPORT-STREAM-DELIVERY | None inventoried. | TCP is a byte stream: a frame may arrive over several `recv` calls (fragmentation) and one `recv` may return several frames (coalescing); `recv` returns the bytes that arrived and does not frame. `0` means the peer closed, after which every call fails with `Disconnected`; a reset surfaces as `Disconnected` too. | implemented | `a_frame_written_in_fragments_accumulates_across_recv_calls`, `two_frames_written_together_arrive_in_one_recv`, `peer_close_mid_frame_reads_zero_then_every_call_is_disconnected`, `a_connection_reset_surfaces_as_disconnected`, `send_delivers_the_bytes_in_order`, `a_boxed_transport_can_be_driven_from_another_worker_thread` |
| TRANSPORT-FRAMING | None inventoried (Netty `ByteToMessageDecoder` handlers, outside the Modbus file inventory). | `Framer<F>` (`decode`, `encode`, `max_frame_bytes`, sizes in wire bytes) does no I/O and never panics. `decode` removes a frame from the front of the buffer only when it returns one; `Ok(None)` means more bytes are needed; an oversized declared size is `Oversized` (`ResourceLimit`) as soon as the header is complete, before any payload is awaited or allocated; an invalid header is `Malformed` (`MalformedData`); both leave the buffer untouched. `FramedTransport::next_frame` receives until a frame decodes: fragments are assembled, coalesced frames come out of successive calls (the buffered second frame needs no I/O), a 0-byte read is `Disconnected` whether the frame was complete up to the cut or not at all, a full buffer without a frame is `ResourceLimit`, a deadline is `Timeout` and loses nothing. `send_frame` encodes into a scratch buffer and sends one transport frame; over the smaller of the framer and transport frame limits it is `ResourceLimit` with nothing sent. | implemented | `a_frame_delivered_in_three_pieces_is_assembled`, `two_frames_in_one_delivery_come_out_of_two_calls`, `a_delivery_ending_inside_the_next_frame_keeps_the_partial_bytes`, `a_close_inside_a_frame_is_disconnected_at_every_cut`, `a_close_after_the_payload_delivers_the_frame_then_disconnects`, `a_close_with_an_incomplete_frame_names_the_buffered_bytes`, `a_full_buffer_without_a_frame_boundary_is_a_resource_limit`, `a_header_over_the_frame_maximum_fails_before_the_payload_is_awaited`, `next_frame_times_out_at_the_deadline_and_the_next_call_continues`, `a_timeout_in_the_middle_of_a_frame_keeps_the_received_prefix`, `a_frame_over_the_framer_maximum_is_refused_before_sending`, `a_frame_over_the_transport_frame_limit_is_refused_before_sending`, `send_frame_puts_one_encoded_frame_in_the_sent_log_per_call`, `send_frame_with_an_elapsed_deadline_times_out_and_sends_nothing`, `a_request_and_its_fragmented_reply_round_trip`, `framer_complaints_map_to_kinds_and_categories`, `accessors_expose_the_transport_and_give_it_back`, `decode_takes_one_frame_and_leaves_the_rest` (testkit), `decode_never_panics_and_obeys_the_buffer_rules_on_short_inputs` (testkit), doctests `Framer`, `FramedTransport`, `LengthPrefixedFramer` |
| TRANSPORT-RESYNC | None inventoried (Netty closes the channel on a decoder failure). | `FramedTransport::resync(deadline)` realigns the receive stream. Rule: ask the framer to `decode` the front of the buffer; `Ok(Some(frame))` is the boundary (the frame is held for the next `next_frame`); `Ok(None)` with room in the buffer keeps the front (a header the framer accepts, or too short to judge) and receives more; `Err`, or `Ok(None)` with a full buffer, discards one byte and asks again. A frame held by an earlier resync is dropped first. The deadline is the remaining deadline of the request whose timeout triggered the resync, or `Deadline::after(clock.now(), timeouts.request)` from `ConnectionGuard::close` or recovery (D15). Without a boundary before the deadline the result is `Disconnected` (transport `Timeout` kept as the source), and the owner reopens the connection; a closed peer is `Disconnected` too. | implemented | `resync_discards_garbage_until_a_boundary_then_next_frame_succeeds`, `resync_keeps_receiving_when_the_garbage_runs_out_before_a_boundary`, `resync_discards_from_a_full_buffer_that_holds_no_frame`, `resync_completes_a_frame_that_was_half_received_when_a_request_timed_out`, `resync_drops_the_frame_an_earlier_resync_was_holding`, `resync_that_never_sees_a_frame_boundary_fails_disconnected_at_the_deadline`, `resync_with_an_elapsed_deadline_and_nothing_buffered_is_disconnected`, `resync_when_the_peer_closes_is_disconnected`, `only_a_timeout_becomes_the_resync_failure` |
