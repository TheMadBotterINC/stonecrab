# Tools parity record
Baseline: `upstream/manifest.toml`, Apache PLC4X v1.0.0 (tag `v1.0.0`),
commit `ea229918f5d07700e04d7d69ab1645da679cb700`.

State (slice S72, 2026-10-29): the connection cache is implemented (ADR-0030), except
subscription restore (`TOOL-CC-RESTORE`, deferred), and so is the event pump's timer batch
reader (ADR-0031), except the subscription trigger, configuration files and value
transformations (deferred), and Object PLC Mapping (ADR-0033), except the runtime proxy
(`TOOL-OPM-PROXY`, deferred); every other row is as slice S43 left it.
Decision E6 of `docs/POST_ALPHA_PLAN.md` (accepted 2026-10-28) makes the PLC4X tools count
toward parity, starting with the connection cache and Object PLC Mapping (OPM), in milestone
M5 ("Tools in the order E6 sets"). Every other row is `planned` for a milestone or
`deferred` with its reason. The tools that live outside the pinned baseline are pointer rows
only. The integrations (Calcite, Camel, IoTDB, Kafka, NiFi, StreamPipes, Eclipse Ditto) are
not tools; they are tracked in `docs/parity/integrations.md`. Test ids of a `planned` row are
`planned:` names, not existing tests.

Status vocabulary, as used in the Status column:

- `planned (Mn)`: Stonecrab will port the behavior in milestone Mn. The Test ids column
  names at least one planned test, prefixed `planned:`.
- `deferred (<reason>)`: recorded so the omission is visible; Stonecrab does not port it
  now. `deferred (upstream placeholder)` marks a stub that throws or does nothing upstream,
  which does not become an obligation (SPEC, "Compatibility baseline").
  `deferred (outside the pinned baseline)` marks a tool that is not in apache/plc4x at the
  pinned commit; it needs its own tag and commit pinned before any row depends on it.
- `implemented (Sn)`: ported in slice Sn and tested; the Test ids column names the tests,
  and `scripts/parity-check.sh` requires each to exist in the Rust sources. The connection
  cache, Object PLC Mapping and the event pump are tested against the simulator and
  against Modbus TCP over the fake transport.

## Connection cache
Manifest `inventory.tool_connection_cache`. A library, not a driver: `PlcConnectionCache`
implements `PlcConnectionManager`, wraps a connection factory and hands out one lease at a
time per connection string, with queued waiters (CC `cache_class`, PlcConnectionCache.java:77).
It provides none of the six protocol operations. Decision E6 names it first. Slice S68
implements it as `stonecrab::ConnectionCache` (ADR-0030); the tests are in
`crates/stonecrab/tests/core_connection_cache.rs`. The default values the manifest marks
UNCERTAIN were read for S68: idle 5 min, lease 1 min, wait 30 s, ping timeout 5 s, idle ping
threshold 30 s, close timeout 5 s, and a 1 s grace margin on the wait
(PlcConnectionCache.java:82-96).

## Object PLC Mapping (OPM)
Manifest `inventory.tool_opm`. A Java-specific library: `@PlcEntity` types with
`@PlcTag(address, cacheDurationMillis)` fields are subclassed at runtime with ByteBuddy and
their getters and setters are intercepted into reads and writes. Reflection and bytecode
generation have no Rust equivalent, and a derive macro would need a proc-macro crate, which
ADR-0018 rules out. Slice S72 (decisions E6 and E11) implements OPM as a trait,
`stonecrab::PlcEntity`, that a type implements to map its fields to tags, a declarative
macro, `stonecrab::plc_entity!`, that writes the struct and that implementation, and an
`EntityManager` over the connection cache (ADR-0033); the tests are in
`crates/stonecrab/tests/core_entity_manager.rs`, against the simulator and against Modbus
TCP over the fake transport, on the fake clock. What the earlier rows marked UNVERIFIED was
read for S72: a negative `cacheDurationMillis` means "read every time", a field is still
fresh at exactly its duration (`isAfter`), and `SimpleAliasRegistry` is a map from alias to
address that ignores the connection string and replaces an alias registered again
(PlcEntityInterceptor.java:331-342; SimpleAliasRegistry.java:25-74).

## Event pump
Manifest `inventory.tool_event_pump`. A library: batches of named tags on one or more
connections are read when a trigger fires and delivered to listeners, with optional value
transformation. Only the `TimerTrigger` works; the subscription trigger throws. Slice S69
implements the timer batch reader as `stonecrab::EventPump`, `TagBatch` and `BatchEvent`
(ADR-0031); the tests are in `crates/stonecrab/tests/core_event_pump.rs`. What
`TOOL-EP-TIMER` had not read was read for S69: the trigger uses `java.util.Timer` with a
fixed delay, chosen in a comment so that missed ticks do not fire in a burst, and a tick that
arrives while a fetch is in progress is skipped, counted and reported with `onFetchSkipped`
(TimerTrigger.java:115-122, 141-170; TagBatch.java:490-502). A failed fetch starts a pause of
1 s, doubled per further failure up to 60 s and reset by a success (TagBatch.java:84-92,
483-488, 922-942).

## Capture replay
Manifest `inventory.tool_capture_replay`. A command line tool, not a driver: it replays a
recorded PCAPNG capture onto a live network device so passive-mode drivers can be exercised
without the plant. It needs libpcap or Npcap and a real or virtual NIC.
