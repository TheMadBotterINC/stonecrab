# S102 symmetric OPC UA chunk protection

Date: 2026-11-03. Implementation/validation in progress on feat/opcua-symmetric-security;
remaining local gates and hosted CI must pass before merge. ADR-0040 is the committed plan.
No new dependency, feature, public operation or version; opcua stays outside default/full.

## Behavior and boundary

Native Backend uses AWS-LC HMAC verification and CBC encryption/decryption with caller IV,
without implicit padding. The private Symmetric engine sends with client keys and receives
with server keys. Sign authenticates but does not encrypt/pad; SignEncrypt authenticates
header/sequence/body/padding and encrypts only bytes after the clear 16-byte header.
The signature covers the final on-wire size, type/flag, channel, token and all clear data.

Receive bounds actual bytes before copying; only the clear header/channel/token are read
before AES/HMAC. The sequence and service payload are parsed only after MAC and padding
validation. Any malformed protected framing, wrong channel/token/type, AES, MAC, padding
or backend receive failure is one Authentication error with fixed text and no source.
Actual input over its ceiling is ResourceLimit before crypto/allocation. This verifies
error shape and validation order, not full-path equal timing or a CBC side-channel proof.

Each install derives both key directions before replacing either active key set, so
failed renewal leaves current/previous intact. Re-derive on each new token, including
changes in either nonce alone. Reject zero/active-reused ids; retain only current and
previous, with explicit previous-token retirement. No nonce cache, timer, task or unbounded
map. Token expiry/grace and secure network execution remain S108/S106; the None lane and
public secure-policy refusal stay unchanged. Key formatting uses Secret redaction; no
zeroization claim. Only CRYPTO-SYMMETRIC closes. CRYPTO-PADDING stays planned for its RSA
half in S105; policy/mode operational rows remain S106/S107.

## Independent vectors and adversarial checks

NIST AES-CBC vectors exercise the production wrappers, in addition to S101's direct
provider adoption checks. Native HMAC verify delegates to AWS-LC hmac::verify, whose
1.19.0 source compares its computed tag with constant_time::verify_slices_are_equal.
Tests change every tag byte and exercise wrong lengths/keys/messages; no timing benchmark
is presented as proof of the primitive's constant-time implementation.

Wire fixture: Python hmac.digest P_SHA256, client_nonce=bytes(range(32)),
server_nonce=bytes(range(32,64)), client-sending secret=server_nonce/seed=client_nonce.
Split signing/encryption/IV per S101; HMAC over MSGF, final little-endian size,
channel=17, token=29, sequence=7, request=9, payload=01 02 03 04 05 and padding.
CBC bytes are independently generated by openssl enc -aes-128-cbc/-aes-256-cbc -nopad
with those key/IV values. Sign, AES128 and AES256 exact bytes are committed in tests.
Padding count is the minimum 0..15; size byte and all extra bytes equal that count,
matching pinned PLC4X BaseEncryptionHandler.java:75–137. Zero count still has a size byte.
Receive also accepts authenticated consistent extra full padding blocks up to byte count255.

Tests cover all three policies, both modes, MSG/CLO, all chunk flags, empty and boundary
bodies/ceilings, reflection, every wire byte tampered and every truncation, signed invalid
metadata and authenticated malformed padding. Re-signed invalid metadata is necessary:
ordinary tampering would also fail MAC, masking a regression in the independent header
checks. The first mutation run found that gap; dedicated signed type/size/channel/token
cases now reject before provider work. No mutation exclusion is added.

The new fuzz_opcua_symmetric uses two selectors then bounded protected bytes. Fixed public
fixture nonces are [1;32]/[2;32], not production defaults. Initial authentication failure
is an ordinary refusal; accepted frames must canonically re-protect and reopen with peer
keys. Seeds include 24 Python/OpenSSL policy/mode/MSG-flag/CLO packets, authenticated bad
padding packets, truncated input and empty input. Existing targets are retained.

Sources: OPC UA Part 6 §6.7.2.5.1 and §6.7.6, and the pinned PLC4X source in ADR-0040.
https://reference.opcfoundation.org/specs/OPC-10000-6/6.7.2.5.1
